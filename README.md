# 국내 ETF 시장 데이터 자동 수집 · 검증 · 일일 리포트

공공데이터포털 **금융위원회_증권상품시세정보(V2) Open API**로 국내 상장 ETF 전 종목의 일별 데이터를 수집하고,
데이터를 자동 검증한 뒤 운용사·테마별 분석 리포트(Excel)를 만드는 Python 프로그램입니다.

- 수집 기간: 2025-01-02 ~ 2026-10-08 (429거래일)
- 대상: 상장 ETF 전 종목 (최신일 1,172개, 순자산 458.6조 원)
- 도구: Python (requests, pandas, openpyxl)

---

## 1. 무엇을 하나요

```
Open API 수집 ─▶ 브랜드→운용사 매핑 ─▶ 6가지 자동 검증 ─▶ 분석 ─▶ Excel 리포트(7개 시트)
   (증분 수집)     (리브랜딩 반영)        (원인별 분류)
```

| 단계 | 내용 |
|---|---|
| 수집 | 처음 실행 시 전체 기간을 받고, 이후에는 **마지막 수집일 이후만 추가 수집** (실행 한 번으로 매일 갱신) |
| 정리 | 종목명 앞 브랜드로 운용사 구분. KBSTAR→RISE, ARIRANG→PLUS, KOSEF→KIWOOM, TIMEFOLIO→TIME 등 **브랜드 변경 반영** |
| 검증 | 중복 / 순자산 누락 / NAV 괴리율 / 수집 누락일 / 미분류 브랜드 / 점유율 합계 |
| 분석 | 운용사별 점유율과 전월말 대비 변화, 월말 점유율 추이, 테마별 자금 흐름(TIGER 점유율), 신규 상장, TIGER 상위 20 |

## 2. 데이터 검증과 규칙 보완

결과를 믿고 쓰려면 숫자보다 **기준**을 먼저 확인해야 한다고 생각해, 1차 실행 결과를 보고 검증 규칙을 고쳤습니다.

| 점검 항목 | 1차 실행 | 원인 | 보완 후 |
|---|---|---|---|
| 운용사 미분류 | 51종목 (순자산 2.2%) | 브랜드 변경(TIMEFOLIO→TIME), 사전에 없던 운용사(IBK, HK, MIDAS 등) | **0종목** |
| NAV 괴리율 ±3% 초과 | 6,420건 (원인 구분 없음) | 해외 기초 ETF의 NAV 산정 시차, 거래정지 종목 | 해외 기초 5,352건 / 거래정지 의심 432건 / **실제 점검 대상 636건(9.9%)** |

- 해외 기초 경고가 가장 많이 몰린 날은 **2025-04-07(253건)** 이었습니다. 해외 ETF의 NAV는 현지 전일 종가를 반영하기 때문에, 시장이 급변한 날에는 국내 가격과 시차가 크게 벌어집니다.
- 거래정지 의심 432건은 대부분 한 종목(ACE 러시아MSCI(합성), 거래대금 0원)에서 나왔습니다.
- 다음 개선 과제: 실제 점검 대상 636건 중 레버리지·인버스·단일종목 상품을 별도 기준으로 분리하기.

|---|---|---|---|

- **채권혼합형:** '채권' 키워드로 묶여 있던 채권혼합형을 별도 테마로 분리하자 18.0조 원 규모 시장이 드러났습니다. 퇴직연금 계좌의 안전자산 한도로 투자할 수 있어 연금 자금이 들어오는 영역인데, TIGER 점유율은 8.9%입니다. 경쟁사 단일 상품(RISE 삼성전자SK하이닉스채권혼합50)이 7개월 만에 4.1조 원을 모았습니다.

## 4. 실행 방법

```bash
pip install requests pandas openpyxl
python etf_market_report.py
```

1. [공공데이터포털](https://www.data.go.kr)에서 "금융위원회_증권상품시세정보" 활용신청 후 일반 인증키를 발급받습니다.
2. 실행하면 인증키를 묻습니다. 자동 실행 시에는 환경변수 `DATA_GO_KR_KEY`에 넣어 둡니다.
3. 같은 폴더에 `ETF_시장리포트_YYYYMMDD.xlsx`가 생성됩니다.
4. Windows 작업 스케줄러에 등록하면 매일 아침 리포트가 자동으로 갱신됩니다.

> 인증키는 코드에 저장하지 않습니다. 원본 데이터(`etf_raw.csv`)는 용량 때문에 저장소에 올리지 않았습니다.

## 5. 개발 방식

AI 코딩 도구로 코드 초안을 만들고, 실행·오류 해결·결과 검증은 직접 했습니다.
예를 들어 첫 실행에서 401 오류가 났을 때, API가 V2로 개편되며 주소가 바뀐 것을 확인해 수정했습니다.
